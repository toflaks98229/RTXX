# DCSS 타일을 활용한 전투 HUD 기획서

> 대상: RTXX 전투 화면
> 자산 출처: crawl `stone_soup-0.34` — `crawl-ref/source/rltiles/`
> 작성 근거: 현재 HUD(`UI_Command_Bar`, `UI_Army_Banner`) 실측 + DCSS 자산 조사

---

## 1. 현재 상태 진단

### 1-1. 이미 계산되지만 화면에 없는 것들

이 프로젝트는 토탈워급 전투 규칙을 **전부 계산하고 있습니다.**
그런데 그중 상당수가 플레이어에게 보이지 않습니다.

| 시뮬레이션이 계산하는 것 | 화면 표시 | 플레이어가 알 수 있는가 |
|---|---|---|
| 사기 (0~100, 4단계) | 게이지 | O |
| **사기 모디파이어 10종** | **없음** | **X — 왜 떨어지는지 모름** |
| 피로 (6단계) | 텍스트 | 세모 |
| 태세 (5종) | 텍스트 | 세모 |
| 병종 상성 | **없음** | **X** |
| 탄약 (`ammunition`) | **없음** | **X** |
| 전과/교환비 | 카드 숫자 | O (2순위 작업) |
| 고지 우위 (`highGroundRate`) | **없음** | **X** |

**가장 큰 문제는 사기 모디파이어입니다.** `Morale_Modifiers`가
`casualties / surrounded / outnumbered / fatigue / flag / alliedRouting /
winning / shock / terrain / general` 10개 항목을 이미 개별로 들고 있는데,
화면에는 합계만 게이지로 나옵니다.

토탈워에서 플레이어는 사기 툴팁의 `-12 포위됨 / -8 사상자 / +10 장군 근처`를
읽고 다음 수를 정합니다. 그 화면이 없으면 부대가 왜 무너지는지 끝내 알 수 없고,
정교하게 만든 사기 시스템이 '가끔 부대가 도망가는 랜덤'으로 체감됩니다.

### 1-2. 현재 HUD의 한계

`UI_Command_Bar`와 `UI_Army_Banner`는 **IMGUI(OnGUI)로 그린 사각형과 텍스트**입니다.

- 장점: Canvas 배선이 없어 컴포넌트 하나로 동작. 부대 수십 개 규모에 충분
- 한계: **아이콘이 없어 전부 글자로 설명**해야 함

병종/태세/상태를 한글 텍스트로 적으면 카드가 글자로 가득 차고,
난전 중에 눈으로 훑기 어렵습니다. 아이콘이면 한 번에 읽힙니다.

## 2. DCSS에서 가져올 것

### 2-1. 자산 조사 결과

```
crawl-ref/source/rltiles/gui/     1,003장
  skills/        무기·방어구·마법 아이콘   32x32
  abilities/     능력 아이콘               32x32
  spells/        주문 아이콘               32x32
  backgrounds/   직업 문장                 32x32
  checkbox.png, tab_label_*.png            20x20
  prompt_yes/no.png                        32x32

crawl-ref/source/rltiles/item/    1,111장
  무기·방패·갑옷 아이콘                    32x32
```

**전부 32x32(일부 20x20)이며, 이미 가져온 타일과 같은 규격입니다.**
같은 아틀라스에 넣을 수 있어 드로우콜이 늘지 않습니다.

### 2-2. 쓸 것과 쓰지 않을 것

| 자산 | 판단 | 이유 |
|---|---|---|
| `item/` 무기·방패 아이콘 | **채택** | 병종 표시에 그대로 씀 |
| `gui/skills/` 아이콘 | **채택** | 태세·상태 아이콘으로 전용 |
| `gui/checkbox`, `tab_label_*` | **채택** | 토글·탭 UI |
| `gui/backgrounds/` 직업 문장 | 보류 | 이 게임에 직업 개념이 없음 |
| `gui/spells/`, `abilities/` | 보류 | 주문·능력 시스템이 없음 |
| DCSS의 패널/프레임 | **없음** | 조사 결과 프레임 이미지가 없음 |

**중요 — 프레임은 가져올 수 없습니다.**
DCSS는 패널 테두리를 이미지가 아니라 코드로 그립니다.
따라서 현재 IMGUI 팔레트(어두운 양피지 + 금색 테두리)를 유지하고,
그 위에 DCSS **아이콘만** 얹는 방식이 맞습니다.

## 3. 설계

### 3-1. 원칙

1. **기존 IMGUI 구조를 유지합니다.**
   Canvas로 갈아엎으면 배선 작업이 커지고, 부대 수십 개 규모에서는
   IMGUI로 충분합니다. 아이콘만 `GUI.DrawTexture`로 덧그립니다.

2. **아이콘은 글자를 대체하되, 글자를 없애지 않습니다.**
   아이콘만 두면 처음 보는 플레이어가 뜻을 모릅니다.
   카드에는 아이콘, 툴팁에는 글자를 둡니다.

3. **정보 밀도를 계층으로 나눕니다.**
   - 1층(항상 보임): 부대 카드 — 병종·인원·사기·전과
   - 2층(마우스 오버): 사기 내역 툴팁 — 모디파이어 10종
   - 3층(전투 종료): 전과 보고서 — 이미 구현됨

### 3-2. 부대 카드 개선안

```
현재                          개선안
┌──────────────┐            ┌──────────────┐
│ 창병          │            │ [창] 창병  [벽]│  <- 병종/태세 아이콘
│ 142/160  지침 │            │ 142/160   [피]│  <- 피로 아이콘
│ ⚔ 37   1.4:1 │            │ ⚔ 37    1.4:1│
│ ████████░░   │            │ ████████░░   │
│ 교전 · 창벽   │            │ ▲고지  ⚠포위  │  <- 상황 아이콘
└──────────────┘            └──────────────┘
```

**추가되는 정보:**
- 병종 아이콘 (`item/` 무기 타일)
- 태세 아이콘 (방패벽/창벽/산개)
- 피로 단계를 색+아이콘으로
- **고지 우위**, **포위** 같은 현재 상황 표시 — 지금은 전혀 안 보임

### 3-3. 사기 툴팁 (핵심)

카드에 마우스를 올리면 사기 내역을 항목별로 펼칩니다.

```
┌─ 사기 62 / 100 ────────────┐
│  -18  사상자 (11%)          │
│  -12  포위됨 (2개 부대)     │
│   -8  피로 (지침)           │
│   -5  수적 열세             │
│  +10  장군 근처             │
│   +6  고지 점령             │
│   +4  깃발                  │
├────────────────────────────┤
│  = 62  (동요)               │
└────────────────────────────┘
```

**이 화면이 이 기획서의 목적입니다.**
`Morale_Modifiers`가 이미 이 값들을 들고 있으므로 **읽어서 그리기만** 하면 됩니다.
시뮬레이션은 한 줄도 건드리지 않습니다.

### 3-4. 탄약 표시

궁병 카드에 남은 화살을 표시합니다.
`ammunition`이 구현되어 있는데 화면에 없어, 플레이어가 언제 화살이
떨어지는지 알 수 없습니다. "지금 쏠 것인가 아낄 것인가"라는 판단이
성립하려면 보여야 합니다.

## 4. 구현 단계

각 단계는 독립적으로 동작하고 검증 가능해야 합니다.

### 1단계 — 아이콘 자산 가져오기 (위험 없음)

- `DCSS_Tile_Importer`에 `gui`, `item` 폴더 추가
- 아틀라스에 함께 담김 (드로우콜 증가 없음)
- **검증**: 아틀라스 보고서에서 페이지 1장 유지 확인

### 2단계 — 아이콘 조회 계층

- 병종/태세/상태 -> 스프라이트 대응표를 만드는 정적 클래스
- IMGUI에서 쓰려면 `Sprite`가 아니라 `Texture2D`와 UV가 필요
  (아틀라스 스프라이트는 `sprite.texture` + `sprite.textureRect`로 꺼냄)
- **검증**: 대응표에 빠진 항목이 없는지 에디터에서 확인

### 3단계 — 부대 카드에 아이콘 적용

- 기존 텍스트를 아이콘으로 교체 (툴팁용 텍스트는 유지)
- 카드 높이 재조정
- **검증**: 60개 부대 화면에서 카드가 겹치지 않는지

### 4단계 — 사기 툴팁 (핵심)

- 마우스가 올라간 카드의 `Morale_Modifiers`를 항목별로 그림
- 0인 항목은 생략 (항상 10줄이면 읽히지 않음)
- **검증**: 실제 전투에서 값이 상황과 일치하는지

### 5단계 — 상황 아이콘 / 탄약

- 고지, 포위, 탄약 소진 등 즉시 판단이 필요한 것만
- **검증**: 아이콘이 과하지 않은지 (카드가 아이콘밭이 되면 실패)

## 5. 위험과 대응

| 위험 | 내용 | 대응 |
|---|---|---|
| **아틀라스 비대** | gui+item 2,114장 추가 | 조사 결과 트림 후 60% 점유. 4096 한 장이면 여유 있음 |
| **IMGUI 비용** | 아이콘 DrawTexture가 늘어남 | 부대 수십 개 규모. 유닛 단위가 아니므로 문제없음 |
| **아이콘 의미 불명** | 처음 보면 뜻을 모름 | 툴팁에 글자 병기. 아이콘만으로 대체하지 않음 |
| **정보 과부하** | 카드가 아이콘으로 가득 참 | 1층은 4개 이하로 제한. 나머지는 툴팁으로 |
| **라이선스** | crawl 자산 사용 조건 | crawl은 GPL2+. 타일 자산도 동일 조건 — **배포 시 확인 필요** |

### 라이선스에 대해

**이 항목은 코드로 해결할 수 없어 명시적으로 남깁니다.**

crawl은 GPL v2+ 라이선스입니다. 타일 자산 중 일부는 별도 크레딧을
요구하는 것이 있습니다(`crawl-ref/licence.txt`, `CREDITS.txt` 참고).

현재는 개발 중이므로 문제가 없지만, **배포한다면 다음이 필요합니다.**
- 라이선스 고지 포함
- 타일 제작자 크레딧
- GPL 전파 조건 검토 (자산만 쓰는 경우의 해석은 법률 판단 영역입니다)

대안: 자체 제작 또는 CC0 타일셋으로 교체.

## 6. 이 기획서가 하지 않는 것

- **Canvas/UGUI 전환**: 지금 규모에서 이득이 없습니다
- **주문·능력 UI**: 그 시스템이 게임에 없습니다
- **인벤토리**: 부대 단위 게임이라 개별 장비 관리가 맞지 않습니다
- **미니맵**: 별도 기획이 필요하며 이 문서 범위 밖입니다
