# 유닛이 지면에 잠기는 문제 — 원인 4가지

> 실측 근거: 9,600명 규모, `-forceRout` 700틱 검증

## 증상

- 부대를 선택해도 선택 UI(링)가 보이지 않음
- 패주 시 병사가 지면에 반쯤 잠긴 채 이동
- 평지에서는 드러나지 않고 지형이 있는 맵에서만 발생

## 원인은 하나가 아니라 넷이며, 겹쳐서 나타납니다

### ① 선택 UI가 발밑 아래에 있음

유닛 프리팹의 자식 로컬 Y:

| 자식 | 로컬 Y |
|---|---|
| Unit_Sprite | **+0.5** |
| Unit_Weapon / Unit_Shield | 0 |
| **Unit_UI (선택 링)** | **−0.5** |

`unit_Data.position`은 **유닛의 발** 위치입니다. 선택 UI가 그보다 0.5m 아래에
있으므로 지형이 있으면 통째로 땅속에 묻힙니다. 평지(y=0)에서는 우연히
가려지지 않아 오랫동안 드러나지 않았습니다.

**수정**: `UI_Unit._Start`가 로컬 Y를 지면 위로 보정합니다.
프리팹이 아니라 코드에서 고친 이유는, 같은 컴포넌트가 부대 진형 마커로도
쓰이기 때문입니다. 한 곳에서 규칙을 정해야 두 용도가 어긋나지 않습니다.

### ② 지면 동기화 지연 (패주에서 두드러짐)

지면 높이는 기본 4틱에 나눠 갱신됩니다. 그 사이 유닛은 옛 높이를 유지합니다.

```
일반 이동  3.0 m/s → 4틱에 20 cm 어긋남
패주       4.8 m/s → 4틱에 32 cm 어긋남   (rout_Speed_Rate 1.6배)
```

패주에서만 유독 심한 이유가 이것입니다.

**수정**: 패주(MoveEscape)나 돌격(MoveCharge) 중인 부대가 있으면
그 틱의 지면 갱신 주기를 1로 좁힙니다. 두 상태는 드물게 일어나므로
평균 비용은 거의 늘지 않습니다. (`Controller_Collision._Schedule_Ground_Sync`)

### ③ 스프라이트 상하 진동(셰이더)의 진폭 과다

`Sprite_Animation.shadergraph`는 `Time → Sine → VertexDescription.Position`으로
스프라이트를 위아래로 흔듭니다. 머티리얼 값이 `_moveLength: 0.3`이었습니다.

```
스프라이트 로컬 y = 0.5
진폭 0.3 → 최저점 0.5 − 0.3 = 0.2 m
②의 지연 0.32 m와 겹치면 → 0.2 − 0.32 = −0.12 m (지면 아래)
```

**수정**: `_moveLength` 0.3 → **0.15** (최저점 0.35m 확보).

> **주의**: 이 값을 다시 0.3 근처로 올리면 같은 문제가 재발합니다.
> 올리려면 `Unit_Sprite`의 로컬 Y도 함께 올려 최저점을 0.3m 이상으로
> 유지해야 합니다.

### ④ 부대 기준점이 지면에 맞춰지지 않음

`Unit_Ground_Sync`는 **유닛만** 지면에 붙입니다. 부대 기준점
(`formation_Move_Transform`)은 대상이 아니었습니다.

기준점 Y는 `locationMoveTo`(= `formation[0]`)에서 오고, 그 Y는 명령 시점의
기준점 Y를 그대로 물려받습니다. **한 번 어긋나면 명령을 내릴 때마다 계속
어긋난 채 이어집니다.** 기준점이 잠기면 진형 슬롯도 함께 잠기고,
유닛은 '땅속의 자리'를 향해 걷습니다.

**수정**: `Move_Stop`과 `Set_Army_Move_Position`이 기준점을 대입할 때
`Snap_To_Ground`를 거칩니다.

## 프로브가 왜 놓쳤는가

두 가지 이유였고 둘 다 보완했습니다.

1. **시뮬레이션만 검사** — `unit_Data.position`을 지면과 비교했을 뿐,
   화면에 보이는 **Transform**은 보지 않았습니다.
   → `Transform차` 항목 추가

2. **패주가 일어나지 않았음** — 기존 검증은 붕괴 0회여서 패주 경로가
   아예 실행되지 않았습니다.
   → `-forceRout`으로 강제해야 재현됩니다

## 검증 (`-forceRout`, 700틱)

```
사망 566명 / 붕괴 10회      ← 패주가 실제로 발생
최대 이격    : 0.00 m
패주 이격    : 0.00 m (표본 1440회)
패주 기준점  : 0.07 m
Transform차  : 0.00 m
```

## 재현 방법

```bash
Unity.exe -batchmode -projectPath . \
  -executeMethod Mass_Battle_Runner.Run_From_CLI \
  -runTicks 700 -seed 12345 -profile -forceRout -out rout.txt
```

`-forceRout`이 없으면 패주가 일어나지 않아 이 문제군을 전혀 검증하지 못합니다.
