# 토탈워식 전투 UI — 조사 보고서 및 기획

> 대상: RTXX 전투 화면
> 기준 게임: Total War 시리즈 (Rome/Medieval II/Shogun 2/Attila 계열)
> 작성 근거: 현재 구현 전수 조사 + 시뮬레이션이 이미 계산하는 값 대조

---

## 1. 조사 — 토탈워 전투 UI의 구성

토탈워의 전투 HUD는 **"카메라를 돌리지 않고도 전군을 지휘할 수 있는가"**
하나를 위해 설계되어 있습니다. 구성 요소는 다음과 같습니다.

### 1-1. 화면 하단 — 부대 카드 바 (핵심)

전군을 한 줄로 늘어놓고, 카드 하나당 다음을 표시합니다.

| 정보 | 표시 방식 |
|---|---|
| 병종 | 아이콘 |
| 인원 | 숫자 + 막대 |
| 사기 | 색 막대 (붕괴 임박 시 점멸) |
| 피로 | 아이콘/색 |
| 상태 | 교전·패주·돌격 등 |
| 선택 여부 | 테두리 강조 |

카드는 **클릭으로 선택**, **더블클릭으로 카메라 이동**이 관례입니다.

### 1-2. 화면 상단 — 전황 요약

- 양측 병력비 막대
- 남은 시간 / 승리 조건
- 전투 단계 (배치 / 교전 / 종료)

### 1-3. 좌하단 — 미니맵

전장 전체와 부대 위치를 점으로 표시. **측면 기동과 우회를 감지하는
유일한 수단**이라 토탈워에서 가장 자주 보는 UI입니다.

### 1-4. 우하단 — 명령 패널

태세·진형·특수 명령 버튼. 단축키와 1:1 대응합니다.

### 1-5. 월드 오버레이 (화면이 아니라 전장 위에 그리는 것)

- **부대 깃발**: 부대 머리 위에 떠서 이름·사기를 표시
- **선택 링**: 선택된 부대의 병사 발밑
- **명령 미리보기**: 우클릭 드래그 시 목적지와 전열 방향을 실선으로
- **경로선**: 이동 명령 시 현재 위치 → 목적지

## 3. 기획 — 무엇을 만들 것인가

### 3-1. 미니맵 (1순위)

**왜 이것이 1순위인가:**
이 게임은 **측후방 공격이 방어력과 방패를 무력화**합니다. 즉 우회가
가장 강력한 전술인데, **플레이어는 우회당하는 것을 볼 방법이 없습니다.**
카메라 밖에서 기병이 돌아 들어와도 부대가 무너지고 나서야 압니다.

미니맵이 없으면 이 게임의 핵심 전술이 한쪽(플레이어가 당하는 쪽)으로만
작동합니다.

**설계:**
```
좌하단 정사각 패널 (200x200px)
  - 전장 경계를 사각형으로
  - 부대를 점으로 (아군 파랑 / 적군 빨강)
  - 점 크기 = 인원 비율
  - 붕괴한 부대는 흐리게
  - 카메라 시야를 사다리꼴로 표시
  - 클릭하면 그 지점으로 카메라 이동
```

**구현 근거:**
`Army.GetPosition()`이 이미 부대 중심을 틱당 한 번 캐시합니다.
부대는 수십 개이므로 IMGUI로 점을 찍어도 비용이 없습니다.
전장 경계는 부대들의 바운딩 박스로 자동 산출합니다.

### 3-2. 명령 미리보기 (2순위)

**현재 문제:**
우클릭 드래그로 진형을 그릴 때 **깃발 두 개(Flag1/Flag2)만** 보입니다.
그 사이에 부대가 어떻게 늘어설지, 어느 쪽을 볼지는 보이지 않습니다.

**설계:**
```
드래그 중:
  - 시작점 ~ 끝점을 실선으로 (전열축)
  - 그 선에 수직으로 짧은 화살표 (부대가 볼 방향)
  - 선을 부대별 구간으로 나눠 표시 (여러 부대 선택 시)
  - 선 길이에 따른 열 수를 숫자로
```

**구현 근거:**
`Controller_Formation.Set_Army_Formation(false)`가 이미 드래그 중
매 프레임 진형을 계산하고 있습니다(`bMove=false` 경로). 그 결과를
그리기만 하면 됩니다. 시뮬레이션은 건드리지 않습니다.

### 3-3. 명령 패널 (3순위)

태세 5종을 버튼으로. 단축키 1~5가 이미 있으므로 그 입구를 재사용합니다.
버튼에는 아이콘(이미 가져온 `gui_skills_*`)과 단축키 숫자를 함께 표시합니다.

### 3-4. 부대 그룹 (4순위)

`Controller.armies_Selected`가 이미 선택 목록을 들고 있어 저장/복원만
추가하면 됩니다.

**단축키는 Ctrl+숫자가 아니라 Shift+F1~F8입니다.**

당초 계획은 RTS 관례대로 Ctrl+숫자였습니다. 그런데 구현하며 확인하니
이 프로젝트에서는 두 키가 이미 다른 뜻을 갖고 있었습니다.

| 키 | 기존 용도 | 정의 위치 |
|---|---|---|
| 숫자 1~5 | 태세 전환 | `Controller.keyCode_Stance_*` |
| Ctrl | 선택 추가(해제 억제) | `Controller.keyCode_disable_clear` |

즉 Ctrl+1은 이미 "선택을 유지한 채 전열 태세로"라는 조합으로 읽힙니다.
여기에 그룹 저장을 겹치면 **Ctrl을 누른 채로는 태세 단축키가 동작하지
않게 되어**, 사용자가 원인을 알 수 없는 방식으로 기능이 사라집니다.

관례를 지키려고 이미 있는 기능을 망가뜨리는 것보다 비어 있는 F 키를
쓰는 편이 낫다고 판단했습니다. 단축키는 인스펙터에서 바꿀 수 있으므로,
태세를 다른 키로 옮기면 언제든 관례로 되돌릴 수 있습니다.

```
Shift + F1~F8  현재 선택을 그룹에 저장
F1~F8          그룹 호출 (기존 선택은 해제)
```

빈 그룹을 호출하면 아무 일도 하지 않습니다. 선택만 풀어 버리면
실수로 눌렀을 때 지휘를 잃기 때문입니다. 반대로 아무것도 선택하지 않은
채 저장하면 그룹이 비워지며, 이것이 그룹을 지우는 방법입니다.

## 4. 하지 않을 것과 그 이유

| 항목 | 이유 |
|---|---|
| **Canvas/UGUI 전환** | 부대 수십 개 규모에서 IMGUI로 충분. 배선 비용만 큼 |
| 유닛 개별 선택 | 이 게임은 부대 단위 지휘가 전제 |
| 인벤토리/장비 관리 | 부대 단위라 개별 장비 개념이 없음 |
| 스킬/주문 UI | 그 시스템이 게임에 없음 |
| 3D 명령 화살표 | 월드에 메시를 그려야 함. 미니맵이 같은 문제를 더 싸게 해결 |

## 5. 위험

| 위험 | 대응 |
|---|---|
| **정보 과부하** | 미니맵과 명령 패널을 동시에 넣으면 화면이 좁아짐. 1순위부터 하나씩 넣고 그때마다 확인 |
| IMGUI 비용 증가 | 미니맵은 부대 수십 개 점만 찍음. 유닛 단위가 아니므로 문제없음 |
| 미니맵 좌표 변환 | 전장 경계 산출이 틀리면 점이 엉뚱한 곳에 찍힘. 부대 바운딩 박스로 자동 산출하고 여유를 둠 |
| 조작 충돌 | 미니맵 클릭이 부대 선택 드래그와 겹칠 수 있음. 미니맵 영역 안의 입력은 소비 처리 |

## 6. 진행 순서

```
1) 미니맵          <- 전술의 절반이 여기 달려 있음
2) 명령 미리보기    <- 드래그가 무엇을 뜻하는지 보이게
3) 명령 패널        <- 단축키를 모르는 사람도 쓸 수 있게
4) 부대 그룹        <- 대규모 전투 조작 편의
```

각 단계는 독립적으로 동작하며, 하나 끝날 때마다 화면에서 확인한 뒤
다음으로 넘어갑니다.

## 7. 구현 결과

네 단계 모두 구현했습니다. 두 어셈블리(`Assembly-CSharp`,
`Assembly-CSharp-Editor`) 컴파일 오류 0개입니다.

| 단계 | 파일 | 조작 |
|---|---|---|
| 1) 미니맵 | `UI/UI_Minimap.cs` | 좌하단, 클릭 시 카메라 이동 |
| 2) 명령 미리보기 | `UI/UI_Command_Preview.cs` | 우클릭 드래그 중 자동 표시 |
| 3) 명령 패널 | `UI/UI_Command_Panel.cs` | 우하단, 클릭 또는 1~5 |
| 4) 부대 그룹 | `UI/UI_Army_Group.cs` | Shift+F1~F8 저장 / F1~F8 호출 |

### 배선

`Gameplay_Setup.Ensure_HUD`가 네 컴포넌트를 Gameplay 오브젝트에 붙이고
`controller` 참조를 채웁니다. 메뉴 **RTXX > 전투 진행 계층 배선**을
실행하면 기존 전투 계층 배선과 함께 한 번에 적용됩니다.

### 아이콘

명령 패널은 `UI_Icons.Get_Stance_Icon`이 돌려주는 DCSS 숙련 아이콘을
씁니다(`gui_skills_shields`, `gui_skills_polearms`, `gui_skills_stealth`,
`gui_skills_dodging`). 기본 태세(Line)는 의도적으로 아이콘이 없으며,
그 칸만 글자로 대신합니다. 전부 아이콘을 달면 '특별한 상태'가 눈에
띄지 않기 때문입니다.

`UI_Icon_Setup.Populate`는 열거형을 돌며 대응표에 물어보는 방식이라,
태세 아이콘이 자동으로 수집됩니다. 이 도구는 고칠 것이 없었습니다.

### 화면 배치 — 겹침 계산

IMGUI는 겹쳐도 경고가 없고 그냥 덮어 그리므로, 각 패널의 높이를 실제로
계산해 맞췄습니다. 처음 잡은 값에 4~62px 겹침이 있어 수정했습니다.

```
화면 하단부터:
  카드 바     10 + 74 + 16          = 100px  (UI_Command_Bar)
  미니맵      106 기준, 190 높이     -> 296px  (UI_Minimap)
  그룹 바     302 기준, 34 높이      -> 336px  (UI_Army_Group)

우하단:
  명령 패널   106 기준, 52 높이      (UI_Command_Panel)
```

즉 좌하단은 **카드 바 → 미니맵 → 그룹 바** 순으로 쌓이고, 명령 패널은
카드 바 오른쪽 위에 놓입니다. 카드 크기나 미니맵 크기를 바꾸면
그 위에 얹힌 것들의 `bottomOffset`도 함께 옮겨야 합니다. 각 필드의
주석에 계산식을 적어 두었습니다.

### 남은 것

- 에디터에서 **RTXX > 전투 진행 계층 배선** 실행 (에디터가 열려 있어
  배치모드로 실행할 수 없었습니다)
- 화면에서 네 가지 배치·가독성 확인. 위 계산은 기본값 기준이므로
  실제 해상도에서 눈으로 확인해야 합니다.
- `marker_facing`은 생성되어 있으나 아직 유닛에 연결되지 않았습니다.
  (프리팹 자식 + `Unit_Transform_Sync`의 회전 동기화가 필요합니다)
